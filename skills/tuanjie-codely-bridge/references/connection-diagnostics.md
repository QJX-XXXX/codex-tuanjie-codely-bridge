# Connection Diagnostics

按层级诊断，不跳过前一层，也不把后一层的成功反推为前一层成功。

1. **项目标识**：确认 `Assets`、`Packages`、`ProjectSettings`、`ProjectVersion.txt` 和团结版本字段；Unity 官方项目停止。
2. **Editor 状态**：确认目标团结 Editor 的规范化路径和版本。Bridge 随目标 Editor 加载，不把包文件存在当作运行状态。
3. **Bridge 前提**：确认当前项目声明了与版本匹配的 Bridge，并且没有把缺失包自动补装当作诊断动作。
4. **CLI 状态**：从明确来源定位绝对 `codely.cmd`，运行 `--version`；记录路径和版本，不记录凭据。
5. **MCP 注册**：读取当前 Agent 所选范围的配置，运行其实际支持的 MCP 列表/状态检查；Codex 可用 `codex mcp list`，只报告注册状态。
6. **实际只读调用**：仅当当前会话真实暴露所需工具时调用；没有工具就报告未完成，不猜名称。
7. **项目根比较**：将 MCP 报告根和当前工作区绝对路径规范化后比较；不一致时停止所有对象写入。

## 常见结论

- CLI 版本成功 + 当前 Agent 的 MCP 列表成功：只能说 CLI 和注册配置通过。
- Editor 打开 + Bridge 随 Editor 加载：说明官方加载流程已发生，仍需 MCP 只读调用证明 Agent 实际可读。
- MCP 工具调用成功但根路径不一致：连接到了错误项目，禁止继续。
- 连接失败后：先重新读取状态判断是否部分成功；只有无副作用的诊断可按原参数重试一次。
