# Package Workflows

所有流程都从项目根、Editor/Bridge、当前 manifest 和实际解析状态开始。使用当前 schema 中真实存在的能力，不凭记忆调用命令。

## 查询

读取目标包的当前版本、来源、依赖和解析状态。若用户要求最新版，先列出实际可用版本和团结 Editor 兼容性，再请求确认目标版本；没有准确包名时停止询问。

## 安装

确认准确包名、来源、目标版本和现有依赖。执行最小安装动作后等待包解析、导入、编译和 Domain Reload；重读 manifest、解析版本和 Console，检查是否产生重复依赖或冲突。

## 升级

读取当前版本和依赖约束，确认目标版本不是未经验证的猜测。升级后等待稳定并重读请求版本与实际解析版本；如果解析失败，保留原配置证据，报告失败，不盲目降级或覆盖其他包。

## 移除

确认包没有被用户保留的直接依赖或项目脚本引用，明确影响范围后才移除。完成后等待解析和编译，重读 manifest、解析结果和 Console；不手工清理 `packages-lock.json`。

## manifest 例外

只有当前 Editor/Bridge 包管理能力确实不可用且用户明确授权时，才可备份后最小修改 `manifest.json`。保留其他依赖、来源和格式；任何 lock 文件变化都由团结 Editor 生成，不由 Agent 手写。
